# 声纹识别（说话人分离）接口说明

适用项目：multi-stream-asr（板端 `/opt/multi-stream-asr`）

功能分两层：

- **说话人分离（diarization）**：在线逐句聚类，给每句标 `S1/S2/...` 标签；不依赖声纹库，未知说话人也能分开。
- **声纹识别（identification）**：句子 embedding 与声纹库做 1:N 比对，命中后把标签替换为真实姓名。

模型：3D-Speaker CAM++（sherpa-onnx `SpeakerEmbeddingExtractor`），默认路径
`/var/lib/sm-sdk/models/speaker/3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx`。

---

## 1. 启用方式

声纹功能默认关闭，启动参数（`main.py`）：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--speaker` | 启用说话人分离 | 关 |
| `--speaker-model PATH` | 指定声纹模型；**给了路径即自动启用** | 上方默认路径 |
| `--speaker-registry PATH` | 声纹库目录；给路径也自动启用 | `<output_dir>/voiceprints` |

板端 systemd 单元已在 `ExecStart` 加 `--speaker`。

启动时会在**子进程**里对模型做预检（缺元数据的 onnx 会让 sherpa-onnx 在 C++ 层段错误），预检失败则打日志并整体关闭声纹功能，不影响转写主流程。

## 2. WebSocket 接口

三条链路行为一致：`/ws/stream`、`/ws/multicast`、`/ws/local_mic`。

### 2.1 transcript 消息中的 speaker 字段

```json
{
  "type": "transcript",
  "lane_id": 0,
  "sentence_id": 3,
  "revision": 2,
  "is_partial": false,
  "is_final": true,
  "segment": {
    "text": "我们今天讨论一下进度。",
    "speaker": {
      "id": "spk_1",
      "label": "S1",
      "name": "张三",
      "confidence": 0.8231,
      "is_provisional": false
    }
  },
  "timestamp_ms": 12345
}
```

| 字段 | 含义 |
|---|---|
| `id` | 机器标识 `spk_1`、`spk_2`…（簇下标 + 1） |
| `label` | 展示标签 `S1`、`S2`…，按首次开口顺序编号 |
| `name` | 声纹库命中的真实姓名；未命中为 `null` |
| `confidence` | 0~1。命中声纹库时为 1:N 比对得分；未命中时为与簇质心的余弦相似度（新建簇固定 1.0） |
| `is_provisional` | `true` 表示未经会话末二次校准（新簇或沿用上句归属时） |

**注意：**

- `speaker` **只出现在 `is_final=true` 的消息上**（离线精修完成后才挂说话人）；partial 消息没有该字段。
- 声纹功能关闭或句段过短（< 1.2s）时，`segment` 里没有 `speaker` 键，前端要做兼容。
- 声纹库为空时只做分离不出姓名（`name` 恒为 `null`）。

### 2.2 speaker_remap 消息（会话末二次校准）

会话结束（`finish`）时做一遍全局重聚类，如标签有变化，在 `saved` 之前下发：

```json
{
  "type": "speaker_remap",
  "lane_id": 0,
  "mapping": { "S3": "S1" }
}
```

`mapping` 为「旧标签 → 新标签」，**必须原子套用整张表**（把本会话已收到的所有 `S3` 一次性替换为 `S1`）。只下发有变化的条目；无变化则不下发。

### 2.3 落盘文件

`output/transcripts/*.txt` 带 `# 说话人` 头部，每句带 `[S1]` / `[张三]` 前缀。

## 3. 声纹库管理（命令行，无 REST 接口）

服务端**没有**注册/列表/删除的 HTTP 接口，统一用脚本：

```bash
cd /opt/multi-stream-asr
PYTHONPATH=src /opt/envs/asr/bin/python scripts/enroll_speaker.py <子命令>
```

| 子命令 | 说明 |
|---|---|
| `--name 张三 --wav a.wav [b.wav ...]` | 注册。建议每人 3 段以上、每段 2~5 秒干净语音；每人最多 8 条，超出淘汰最旧 |
| `--list` | 列出声纹库（含每人条数） |
| `--check probe.wav` | 试识别：打印 Top3 得分并按阈值判定命中，不落盘 |
| `--remove 张三` | 删除 |
| `--registry PATH` | 指定声纹库目录（默认 `output/voiceprints`） |
| `--model PATH` | 指定模型 |

输入 wav：int16，多声道自动混单声道，非 16k 自动重采样。

存储布局（`<registry>/`）：`index.json`（姓名→文件映射）+ 每人一个 `spk_N.npy`（L2 归一化 embedding 矩阵）。

**重要：声纹库只在服务启动时加载一次。运行期间用脚本注册/删除后，需重启服务才生效。**

## 4. 阈值标定

现场远场/混响环境相似度分布与近场不同，上线前应标定：

```bash
# 正式标定：显式分组（一人多段）
PYTHONPATH=src python scripts/speaker_calibrate.py \
  --speaker 张三=a1.wav,a2.wav,a3.wav \
  --speaker 李四=b1.wav,b2.wav,b3.wav

# 快速体检：假设一个文件一个人（会低估类内相似度，仅供粗查）
PYTHONPATH=src python scripts/speaker_calibrate.py \
  --auto-split-dir /path/to/wavs --split-seconds 3.0
```

输出类内/类间余弦分布、`gap = min_intra - max_inter` 及建议阈值：

- `gap > 0.20`：单阈值可用
- `0 ~ 0.20`：需双门限 + 多窗 + 二遍重聚类（当前实现已具备）
- `gap < 0`：区间重叠，需换更近的麦克风/更干净的注册音频

## 5. 主要配置（`SpeakerConfig`，代码内调整，无 CLI）

| 字段 | 默认 | 说明 |
|---|---|---|
| `min_duration_seconds` | 1.2 | 短于此的句子不提 embedding，沿用上句归属 |
| `window_seconds` / `hop_seconds` | 1.5 / 0.5 | embedding 多窗平均 |
| `match_threshold` | 0.55 | 在线聚类：≥此值归入已有簇 |
| `new_speaker_threshold` | 0.45 | <此值开新簇；灰区归入但低置信 |
| `identify_threshold` / `identify_margin` | 0.55 / 0.05 | 声纹库双门限：超阈值**且**领先第二名 margin 才命中 |
| `merge_threshold` | 0.70 | 二遍重聚类合并阈值 |
| `max_speakers` | 8 | 单会话最大说话人数 |
| `sticky_bonus` | 0.05 | 抑制相邻句标签抖动 |
| `enable_second_pass` | true | 会话末全局重聚类（对应 `speaker_remap`） |

## 6. 能力边界与注意事项

- 句级归属，2~4 人场景准确率约 85%（近场）；远场需先标定阈值。
- 每路（lane）独立 embedding 提取器，约 28MB 内存/lane。
- 新模型上线前必须先用 `scripts/patch_speaker_model.py` 补 onnx 元数据，否则进程会直接段错误：

```bash
python scripts/patch_speaker_model.py --input model.onnx --output model.patched.onnx
```
