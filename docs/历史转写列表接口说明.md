# 历史转写列表接口说明

## 接口

```
GET /v1/transcripts?limit=50&offset=0&q=
```

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| limit | int | 50 | 每页条数，范围 1~200 |
| offset | int | 0 | 分页偏移 |
| q | string | 无 | 可选，按文件名/正文预览/纪要预览子串过滤 |

## 如何判断转写类型（重点）

**每个条目都带 `source` 字段，直接用它判断，不要自己猜文件名。**

| source 值 | 含义 | 对应转写入口 |
|---|---|---|
| `multicast` | 组播转写 | 组播音频源（`/ws/multicast` 收听的任务） |
| `stream` | 本机麦克风 | 前端推流（`/ws/stream`） |
| `local_mic` | 板载麦克风转写 | 板载麦克风采集（`/ws/local_mic`） |
| `offline` | 文件转写 | 音频文件上传（`POST /v1/audio/transcriptions`） |
| `unknown` | 旧数据，无来源信息 | 2026-11-17 之前生成的历史文件（旧文件名不带来源） |

前端展示建议映射：`multicast → 组播`、`stream → 本机麦克风`、`local_mic → 板载麦克风`、`offline → 文件转写`、`unknown → 其他`。

**文件名编码规则**（新文件，供展示/排障参考）：

```
{source}-lane{lane号}-{开始转写时间YYYYMMDD-HHMM}.txt
```

例：`multicast-lane3-20261117-1430.txt` = 组播来源、第 3 路、2026-11-17 14:30 开始转写。

## 注意事项

1. **不要依赖文件名前缀猜类型**：旧版文件名统一是 `spacemit-asr-lane*-毫秒时间戳.txt`，四种来源完全相同，无法区分——这正是新增 `source` 字段的原因。`source=unknown` 的历史文件只能显示"其他"。
2. **时间精度到分钟**：同一 lane 同一分钟内多次转写会共用文件名（后者覆盖前者）。测试场景高频起停时如需区分，可结合 `mtime`（落盘时间，精确到秒）判断。
3. 列表按文件修改时间倒序；`q` 过滤是大小写不敏感的子串匹配。
