# 本地音频循环输入设计

## 目标

为 `Default files` 和 `Local WAV` 增加循环输入选项，用于长期展示和老化测试。勾选后，文件输入持续循环直到用户手动停止；未勾选时保持现有自然结束行为。

## 设计决策

- 循环逻辑放在 `LocalWavSource` 内部。文件只读取一次到固定的 WAV 缓冲区，后续循环重复读取该缓冲区，不累积新的音频数组。
- 循环模式不发送自然结束帧；只有用户停止识别时才结束源和 pipeline。`frame_index`、`timestamp_ms` 持续递增，避免重复时间坐标和句 ID。
- `Default files` 与 `Local WAV` 都显示 `Loop audio` 复选框，麦克风输入不显示。复选框状态随 lane 输入草稿提交，并在服务状态中回显。
- 循环模式下结果和模型输出文件保持为空，不保存循环产生的识别文本；停止时仍保存 `config.json` 和完整聚合的 `metrics.json`。
- 不修改 Zipformer 接收、Qwen 请求、离线任务排序、pipeline 分段和模型工作流。

## 内存边界

- `LocalWavSource` 只保留一次文件 PCM 缓冲区。
- `SegmentCache` 和 `OnlineFrameQueue(maxsize=1)` 继续使用现有固定容量。
- `LatencyTracker`、`RtfTracker`、`SharedTimingsTracker` 和 event-loop lag 改为 `count/total/max` 的流式聚合，使用固定内存；报告字段保持不变且统计覆盖整个运行周期。
- 主进程循环运行时每路只保留最近 100 个句级结果；前端每路只保留最近 100 个事件和 revision。完整结果不依赖内存保存。
- 不改变现有 Qwen 任务调度。如果 Qwen 长期慢于输入产生速度，既有离线任务链可能产生背压；本次不丢弃请求、不降级结果，也不修改该工作流。

## 停止和异常

- 手动停止循环源后正常发送结束信号，所有当前 pipeline 清理逻辑保持不变。
- 空 WAV 开启循环时在开始识别前报错，避免空循环占满事件循环。
- 文件读取、格式校验和模型加载错误保持现有错误路径。

## 验证

- `LocalWavSource` 测试循环多轮、帧/时间戳单调递增、手动停止和空文件拒绝。
- 配置/API 测试循环字段仅对文件输入有效，麦克风不接受该字段。
- 指标测试验证长序列不保存全量样本且 `count/total/average/max` 精确。
- UI 测试验证两类文件输入显示复选框、麦克风隐藏、循环字段随提交发送。
- 集成测试验证循环不会自然结束，手动停止后回到可重新开始状态，并保存配置和聚合指标。
