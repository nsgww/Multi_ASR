# 麦克风热插拔稳定身份设计

## 问题

PortAudio 数字索引会在 USB 麦克风热插拔后变化。当前前端按 lane 保存索引，且各下拉框分别刷新，因此刷新一个 lane 后，其他 lane 可能仍持有旧索引并指向错误设备。`sounddevice` 的进程级 PortAudio 实例也可能继续返回初始化时的设备表。

## 设计

- 设备稳定 ID 使用 PortAudio 精确选择器：`设备名, Host API`。
- `/api/audio-devices` 每次在互斥锁内重新初始化 PortAudio，并返回 `id`、当前 `index` 和展示信息；响应禁止 HTTP 缓存。
- 前端每次只接受最新请求的结果，并用同一份最新快照重建所有处于麦克风模式的 lane 下拉框。
- 前端按稳定 ID 保存选择。列表刷新后，同一设备即使索引变化也保持选中，并同步更新仅用于兼容和记录的当前索引。
- 已选稳定 ID 不在新列表中时，保留选择并显示不可用错误；开始识别前阻止提交。
- `LaneInputConfig` 和 API 增加 `microphone_device_id`。后端开始识别时优先按稳定 ID 在刷新后的设备表中解析，旧配置仍可按数字索引工作。
- 麦克风流运行在 lane 子进程；主进程只在列表请求和开始识别前刷新自己的 PortAudio，不影响已加载模型。

## 验证

- 单元测试覆盖 PortAudio 重新初始化、稳定 ID、索引变化后保持选择、缺失设备报错和旧数字配置兼容。
- Web 测试覆盖 `Cache-Control: no-store` 及前端 `fetch` 禁用缓存。
- 开发板验收：加载模型后热插拔四个麦克风，任一路刷新后所有 lane 保持物理设备选择；四路同时开始、持续取帧并正常停止。
