# Multi-Stream ASR 项目全景知识库页设计

## 目标

为产品经理、项目经理、工程师与普通用户建立一份可独立阅读的项目全景介绍。重点解释项目解决的问题、关键能力、模块协作方式、运行可靠性和可用于决策的性能信息；不包含前端操作说明或代码实现细节。

## 读者与叙事

以业务价值开篇：项目在 K3/A100 上支持 2/4/6/8 路音频同时进行在线与离线 ASR，通过 Zipformer 的快速过程文本和共享 Qwen3-ASR 的最终转写平衡响应速度、结果质量和硬件资源利用率。

页面按“核心价值 → 系统全景 → 模块能力 → 单路流程 → 稳定性与指标 → 适用边界”阅读。语言面向非技术读者，必要技术细节仅用于解释边界和取舍。

## 内容与可视化

1. 开篇摘要和三个核心承诺：多路隔离、快速在线反馈、可追踪最终结果。
2. Mermaid 系统全景图：音频源、lane、主控进程、共享 Qwen3-ASR、事件/指标和运行产物的职责边界。
3. 模块说明：音频接入、Zipformer 在线识别、token 时间戳切段、共享 Qwen3-ASR、调度与健康检查、运行产物与度量。
4. Mermaid 单路流程图：100 ms 音频帧、在线文本/endpoint、受保护切段、离线最终识别、事件和落盘。
5. 生命周期与可靠性说明：加载、并行预热、识别、每路收尾、统一停止；输入校验、服务 watchdog、故障收敛与自动化测试范围。
6. 性能表：只呈现经验证的 K3/A100 组合，避免把目标值误写为实测承诺；说明高并发时共享服务队列和丢帧的容量边界。
7. 适用范围与不覆盖内容。

## 正确性与边界

- 明确区分项目支持能力、性能目标和已验证实测数据。
- 说明 0.6B q40 的 2 路为最稳定实测组合；4 路接近目标；更高并发及 1.7B 组合会有排队和丢帧风险。
- 不出现前端流程、命令行操作、具体类名、函数名、代码片段或部署步骤。
- 目标知识库页当前只有标题，使用全文覆盖不会丢失既有正文资源。
