# 声纹识别与说话人分离说明

适用项目：multi-stream-asr（板端 `/opt/multi-stream-asr1`，服务 `multi-stream-asr.service`，端口 8000）

> 接口字段级的详细协议见 [声纹识别接口说明.md](声纹识别接口说明.md)；
> 本文讲当前部署形态、模型、性能实测和运维操作。

## 1. 功能分层

- **说话人分离（diarization）**：在线逐句聚类，每句标 `S1/S2/...` 匿名标签；不需要声纹库，陌生人也能分开。
- **声纹识别（identification）**：句子 embedding 与声纹库 1:N 比对，命中后把标签换成真实姓名；库为空时只做分离。

## 2. 当前模型

板端用的是**自训的 CAMPPlus（CN-Celeb2，epoch_50）**，不是默认的 3D-Speaker 官方模型：

```
/var/lib/sm-sdk/models/speaker/campplus_epoch50_sv_zh-cn_16k.onnx   (28MB)
```

- 本地评测 EER 1.72%（CN-Celeb2 自建测试集，CPU）
- 接入方式：systemd `ExecStart` 里 `--speaker-model` 指向该文件
- 模型导出时修复过 `avg_pool1d(ceil_mode)` 导出 bug，并用 `scripts/patch_speaker_model.py` 打过 sherpa 元数据补丁（关键：`normalize_samples=0`、`feature_normalize_type=global-mean`，否则特征尺度全错、陌生人会误命中）

默认模型（未指定 `--speaker-model` 时）：`/var/lib/sm-sdk/models/speaker/3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx`。

## 3. 启用与配置

systemd（`/etc/systemd/system/multi-stream-asr.service`）：

```
ExecStart=... --speaker --speaker-model /var/lib/sm-sdk/models/speaker/campplus_epoch50_sv_zh-cn_16k.onnx --lanes 8
Environment=SPEAKER_NUM_THREADS=2
```

| 配置 | 默认 | 说明 |
|---|---|---|
| `--speaker` | 关 | 启用分离/识别 |
| `--speaker-model PATH` | 3dspeaker 官方 | 给路径即自动启用 |
| `--speaker-registry PATH` | `<output>/voiceprints` | 声纹库目录 |
| `SPEAKER_NUM_THREADS`（环境变量） | 1 | 声纹提取线程数，K3 上建议 2 |

主要阈值（`SpeakerConfig`，代码内）：`match_threshold=0.55` / `new_speaker_threshold=0.45`（在线聚类）、`identify_threshold=0.55` / `identify_margin=0.05`（声纹库双门限）、`merge_threshold=0.70`（会话末重聚类）。**注意这组阈值是按官方模型调的，epoch_50 在 CN-Celeb2 的 EER 阈值约 0.21，正式用姓名识别前应在现场用 `scripts/speaker_calibrate.py` 重新标定。**

## 4. 运行时行为与性能（2026-10-28 板端实测）

- **embedder 是 lane 级缓存 + 启动预热**：sherpa 加载模型约 **6.5s**，以前每会话首个句子现载，会把该句 FINAL 拖慢 6 秒多；现在服务启动时 8 个 lane 各自预热完毕，会话内只剩纯推理
- 声纹与 Qwen 纠错**并行**跑同一段音频，FINAL 等两者中较慢者
- 单窗（1.5s）推理：2 线程 ≈ 0.2s；4.2s 句子多窗（6 窗）合计 ≈ 1.2s（2 线程）
- 端到端：句尾静音 0.7s 断句 → FINAL ≈ 0.8~0.9s（含纠错+声纹），**说完话到出最终结果约 1.6s**
- 短于 1.2s 的句子不提声纹，沿用上句归属
- 每 lane 独立 embedder，约 28MB 内存/lane

## 5. 声纹库管理（REST 接口，热生效）

板端 REST 接口（注册/删除后**热重载到所有 lane，无需重启**）：

```bash
curl http://<板子IP>:8000/v1/speakers                                  # 列表
curl -X POST http://<板子IP>:8000/v1/speakers -F "name=张三" \
     -F "files=@z1.wav" -F "files=@z2.wav"                             # 注册（1~8 个 wav）
curl -X DELETE http://<板子IP>:8000/v1/speakers/%E5%BC%A0%E4%B8%89     # 删除（name 需 URL 编码）
```

字段/错误码等细节见《声纹识别接口说明.md》第 3 节。

- 建议每人 3 段以上、每段 2~5 秒干净近场语音；混响重的音频不要注册
- 首次注册要加载声纹模型（约 10~20 秒），之后每次约 1~3 秒/段

命令行脚本仍保留（批量/离线操作用）：

```bash
cd /opt/multi-stream-asr1
PYTHONPATH=src /opt/envs/multi-stream-asr/bin/python scripts/enroll_speaker.py --list
PYTHONPATH=src /opt/envs/multi-stream-asr/bin/python scripts/enroll_speaker.py --name 张三 --wav z1.wav z2.wav z3.wav
PYTHONPATH=src /opt/envs/multi-stream-asr/bin/python scripts/enroll_speaker.py --check probe.wav
PYTHONPATH=src /opt/envs/multi-stream-asr/bin/python scripts/enroll_speaker.py --remove 张三
```

**注意：脚本只改磁盘、不触发热重载，用脚本改完需 `sudo systemctl restart multi-stream-asr`（或调一次 REST 注册/删除触发热重载）。**

## 6. WS 输出（摘要）

- `transcript` 消息 `is_final=true` 时 `segment.speaker`：`{id, label, name, confidence, is_provisional}`；`name` 命中声纹库才有值
- 会话结束可能收到 `speaker_remap`（`{mapping: {旧标签: 新标签}}`），需原子替换本会话所有旧标签
- 落盘 `output/transcripts/*.txt` 每句带 `[S1]`/`[张三]` 前缀

## 7. 常见问题

- **FINAL 突然变慢**：先查是不是 CPU 被打满（之前 FaceGuard 视频循环吃了 392% CPU 导致全线变慢）；再查 `SPEAKER_NUM_THREADS` 是否生效
- **陌生人被识别成已注册人**：阈值未按现场标定，跑 `speaker_calibrate.py`；或注册音频太脏
- **句级分离准确率**：近场 2~4 人约 85%；远场必须先标定
