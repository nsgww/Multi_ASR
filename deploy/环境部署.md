# multi-stream-asr 虚拟环境部署说明

实时转写服务（WebSocket + 组播 + 离线校正 + 声纹 + 纪要生成）。

## 环境一览

| 项 | 值 |
|---|---|
| 板端 venv | `/opt/envs/multi-stream-asr` |
| Python | **3.13**（Bianbu 源 `python3.13` + `python3.13-venv`） |
| 代码 | `/opt/multi-stream-asr`（无 git，从本地 `D:\a\k3\multi-stream-asr` 同步） |
| 服务 | systemd `multi-stream-asr.service`，:8000 |

## 系统依赖（apt）

```bash
sudo apt-get install -y python3.13 python3.13-venv \
  libportaudio2 portaudio19-dev libasound2-dev \
  libsndfile1 libspeexdsp1 ca-certificates
```

- `portaudio/libasound`：本地麦克风采集（PyAudio/sounddevice）
- `libsndfile`：音频文件读写
- `libspeexdsp`：组播源重采样（`speexdsp_lib_path`）

## Python 依赖要点

常规包见 `pyproject.toml`（fastapi/uvicorn/numpy/pydantic/pyyaml…）。板端实测关键版本：

| 包 | 版本 | 说明 |
|---|---|---|
| `sherpa_onnx` | 1.13.2 | zipformer 流式识别 + sensevoice，riscv64 定制 wheel |
| `onnxruntime` | 1.24.2+spacemit.a1 | 进迭定制版（silero VAD / 声纹 onnx 推理） |
| `funasr_onnx` | 0.4.3 | paraformer 路径（备用识别器） |
| `PyAudio` / `sounddevice` | 0.2.14 / 0.5.6 | 本地麦 |
| `multi-stream-asr` | 0.1.0 | 项目自身 `pip install -e .` |

**定制 wheel 来源**（脚本已内置，此处备查）：

- 进迭 GitLab PyPI：`https://git.spacemit.com/api/v4/projects/33/packages/pypi/simple`（onnxruntime）
- 进迭 GitLab PyPI：`https://git.spacemit.com/api/v4/projects/81/packages/pypi/simple`（sherpa-onnx）

## 一键部署

```bash
# 全新板子上（root）：
sudo bash deploy/setup_env.sh

# 已有 venv 想重建：
sudo rm -rf /opt/envs/multi-stream-asr && sudo bash deploy/setup_env.sh
```

## 验证

```bash
# 必需依赖（缺了服务起不来）
/opt/envs/multi-stream-asr/bin/python - <<'EOF'
import sherpa_onnx, onnxruntime, sounddevice
print("env OK:", onnxruntime.__version__)
EOF

# paraformer 备用路径（缺了只影响切 paraformer，zipformer 正常）
/opt/envs/multi-stream-asr/bin/python -c \
  "from funasr_onnx.paraformer_online_bin import Paraformer; print('funasr OK')"

sudo systemctl restart multi-stream-asr
curl -s http://127.0.0.1:8000/v1/multicast    # 能返回 {"jobs":...,"max_jobs":8}
```

首次重启 lane 加载约 1-2 分钟，属正常。

> `setup_env.sh` 用 `--no-deps` 装 funasr_onnx（它 pin 了 numpy<=1.26.4，与本栈
> numpy 2.x 冲突），所以脚本会单独补 `jieba` + `kaldi-native-fbank`。后者是 C++
> 扩展，riscv64 没有预编译 wheel 时要源码构建（需 `build-essential cmake
> python3.13-dev`）；装不上只会让 paraformer 备用路径不可用，不影响 zipformer。

## 备注

- `scripts/setup.sh` 是旧版全流程脚本（含从 spacemit model_zoo 下载模型），模型现已改由 OpenStore 管理（`role_runtime.py` 读 `/app/lg-store/database/models/current-roles.json`），新板无需下载 ASR 模型，装环境即可
- 模型切换在 OpenStore 前端操作，切完需重启本服务生效

## 单元文件路径必须与代码目录一致

`deploy/multi-stream-asr.service` 里写死了 `/opt/multi-stream-asr`
（`WorkingDirectory` 和 `PYTHONPATH`）。代码如果放在别的路径（例如新板的
`/opt/Multi-Stream-ASR`），服务会找不到包或跑错目录，先改单元再启动：

```bash
sudo sed -i 's#/opt/multi-stream-asr#/opt/Multi-Stream-ASR#g' \
  /etc/systemd/system/multi-stream-asr.service
sudo systemctl daemon-reload
sudo systemctl restart multi-stream-asr
```

不确定当前单元指向哪：`systemctl cat multi-stream-asr | grep -E 'WorkingDirectory|PYTHONPATH'`。
